# Резервное копирование базы данных UFC Stats

## Описание

Этот каталог содержит резервные копии базы данных приложения UFC Stats. База данных H2 автоматически архивируется для предотвращения потери данных.

## Структура файлов

- `ufc_stats_backup_YYYYMMDD_HHMMSS.zip` - Архивы с резервными копиями БД
- `backup.log` - Лог файл с историей бэкапов
- `README.md` - Этот файл

## Автоматическое резервное копирование

### Настройка cron для ежедневного бэкапа

Добавьте следующую строку в crontab для ежедневного бэкапа в 2:00 ночи:

```bash
# Открыть crontab для редактирования
crontab -e

# Добавить строку:
0 2 * * * /Users/evgenijstolarov/Documents/JavaProjects/ufc_stats/scripts/daily-backup.sh
```

### Настройка cron для еженедельного бэкапа

Для еженедельного бэкапа по воскресеньям в 3:00:

```bash
0 3 * * 0 /Users/evgenijstolarov/Documents/JavaProjects/ufc_stats/scripts/daily-backup.sh
```

## Ручное управление бэкапами

### Создание бэкапа

```bash
cd /Users/evgenijstolarov/Documents/JavaProjects/ufc_stats
./scripts/backup-db.sh backup
```

### Восстановление из бэкапа

```bash
cd /Users/evgenijstolarov/Documents/JavaProjects/ufc_stats
./scripts/backup-db.sh restore /path/to/backup.zip
```

### Просмотр списка бэкапов

```bash
cd /Users/evgenijstolarov/Documents/JavaProjects/ufc_stats
./scripts/backup-db.sh list
```

### Очистка старых бэкапов

```bash
cd /Users/evgenijstolarov/Documents/JavaProjects/ufc_stats
./scripts/backup-db.sh cleanup
```

## Политика хранения

- **Автоматическая очистка**: Старые бэкапы автоматически удаляются, оставляются только последние 3
- **Ручная очистка**: Используйте команду `cleanup` для принудительной очистки
- **Размер бэкапа**: Обычно 1-5 МБ в зависимости от количества данных

## Восстановление после сбоя

1. **Остановите приложение**:
   ```bash
   pkill -f "ufc-stats"
   ```

2. **Восстановите из последнего бэкапа**:
   ```bash
   ./scripts/backup-db.sh restore backups/ufc_stats_backup_YYYYMMDD_HHMMSS.zip
   ```

3. **Запустите приложение**:
   ```bash
   ./gradlew bootRun
   ```

## Мониторинг

Проверяйте лог файл `backup.log` для мониторинга процесса бэкапа:

```bash
tail -f backups/backup.log
```

- Храните бэкапы в безопасном месте
- Рассмотрите возможность копирования бэкапов в облачное хранилище
- Регулярно тестируйте восстановление из бэкапов

## Устранение неполадок

### Ошибка "Файл базы данных не найден"
- Убедитесь, что приложение запущено хотя бы один раз
- Проверьте путь к файлам БД в скрипте

### Ошибка "Не удалось создать бэкап"
- Проверьте права доступа к директории backups
- Убедитесь, что достаточно места на диске

### Ошибка при восстановлении
- Убедитесь, что приложение остановлено
- Проверьте целостность файла бэкапа
